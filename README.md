# ทักษะที่ตลาดแรงงานกาฬสินธุ์ต้องการ

เว็บไซต์ **React + Vite + React Router** นำเสนอทักษะที่สกัดจากประกาศรับสมัครงานจริงในจังหวัดกาฬสินธุ์
ใช้ชุดสีและฟอนต์เดียวกับ [`curriculum-graph`](../curriculum-graph) เพื่อให้อ่านเป็นงานชุดเดียวกัน
แต่แยกโปรเจกต์ ข้อมูล และการ deploy ออกจากกันโดยสิ้นเชิง

## หน้าเว็บ

| เส้นทาง | หน้า | เนื้อหา |
|---|---|---|
| `/` | หน้าแรก | ตัวเลขสำคัญ · ทักษะ 10 อันดับ · สัดส่วนตามหมวดงาน · คุณสมบัติที่ประกาศระบุ · กระจายตามอำเภอ |
| `/skills` | ทักษะที่ต้องการ | Hard skills กรองตามหมวดได้ · Soft skills · ตารางแยกรายหมวด |
| `/jobs` | ตำแหน่งงาน | ประกาศทุกรายการ ค้นหาและกรองตามทักษะ · ลิงก์กลับประกาศต้นทาง |
| `/method` | ระเบียบวิธีและข้อจำกัด | ขั้นตอนการสร้างข้อมูล · หลักการนับ · ตารางแหล่งข้อมูล · ข้อจำกัดที่ทราบ 4 ข้อ |

## แหล่งข้อมูลและสิ่งที่เก็บได้จริง

| แหล่ง | วิธีเข้าถึง | เก็บได้ | อยู่ในกาฬสินธุ์ | เนื้อประกาศ |
|---|---|--:|--:|---|
| **JobThai** | `__NEXT_DATA__` ฝังผล Apollo GraphQL · `province=04` | 28 | 28 | ✅ ครบ |
| **JOBTOPGUN** | HTML เรนเดอร์ฝั่งเซิร์ฟเวอร์ · ไล่หน้าแยกสายงาน | 119 | 4 | ✅ 110 จาก 119 |
| **JOBBKK** | HTML เรนเดอร์ฝั่งเซิร์ฟเวอร์ · สองเส้นทางค้นหา | 35 | 16 | ✅ 34 จาก 35 |

> [!warning] URL ของ JobThai มีสองแบบที่สับสนกันได้
> หน้ารายการลิงก์ไป `/th/company/job/{id}` ซึ่งแสดง**โปรไฟล์บริษัท**
> และซ่อนเนื้องานไว้หลังปุ่ม "ดูรายละเอียดงาน" — ดึงด้วย `fetch` แล้วได้หน้าเปล่า
>
> เนื้อประกาศจริงอยู่ที่ **`/th/job/{id}`** ซึ่งเรนเดอร์ฝั่งเซิร์ฟเวอร์เต็มรูปแบบ

> [!important] หลักการนับ
> **ประกาศที่เก็บมาทั้งหมด** ใช้ตรวจสอบย้อนกลับเท่านั้น ไม่ใช้คำนวณสถิติ
> **ประกาศที่ยืนยันว่าอยู่ในกาฬสินธุ์** เป็นฐานเดียวที่ใช้คำนวณจำนวนงานและสถิติทักษะทุกหน้า
>
> เป็นหลักการเดียวกับที่ `curriculum-graph` แยก `searchMatches` ออกจาก `classifiedMatches`
> เหตุผลคือคำค้น "กาฬสินธุ์" ของ JOBTOPGUN คืนผลระดับภาคอีสานเป็นส่วนใหญ่
> ถ้านับรวมทั้งหมดจะได้ภาพตลาดแรงงานที่เกินจริงหลายเท่า

## ทะเบียนทักษะ

[`scripts/skill-taxonomy-th.mjs`](scripts/skill-taxonomy-th.mjs) เขียนขึ้นใหม่สำหรับตลาดแรงงานระดับจังหวัด
ไม่ได้ใช้ `skill-taxonomy.mjs` ของ `curriculum-graph` เพราะชุดนั้นออกแบบมาสำหรับสาย AI โดยเฉพาะ
(Python, MLOps, LLM) ซึ่งแทบไม่ปรากฏในประกาศงานกาฬสินธุ์

**ชื่อทักษะเป็นภาษาอังกฤษ** เพื่อให้เทียบกับกรอบสากลอย่าง O*NET และ ESCO ได้
พร้อมคำแปลไทยกำกับสำหรับผู้อ่านในพื้นที่ ส่วน pattern จับได้ทั้งสองภาษา
เพราะประกาศงานไทยเขียนผสมกันเสมอ

### เกณฑ์แบ่ง Hard / Soft

ยึดตามนิยามของ [Indeed](https://www.indeed.com/career-advice/resumes-cover-letters/hard-skills-vs-soft-skills)

| | Hard skill | Soft skill |
|---|---|---|
| **นิยาม** | ความรู้หรือการฝึกอบรมเชิงเทคนิค | นิสัยและลักษณะส่วนบุคคล |
| **ได้มาอย่างไร** | การศึกษา ฝึกอบรม เรียนเฉพาะทาง | ประสบการณ์และการปฏิสัมพันธ์ |
| **ใช้ทำอะไร** | งานเชิงเทคนิคที่ระบุได้ | จัดการงานและความสัมพันธ์กับผู้อื่น |
| **ถ่ายโอนข้ามงาน** | ผูกกับสายงาน | ใช้ได้ทุกสายงาน |
| **สอนได้แค่ไหน** | สอนผ่านหลักสูตรได้ตรง | พัฒนายากกว่า ต้องสั่งสม |

**Hard skills 39 รายการ ใน 6 หมวด** — Computer & Digital · Engineering & Manufacturing ·
Business & Finance · Sales & Marketing · Supply Chain & Logistics · Applied Sciences

**Soft skills 13 รายการ** ใช้ชุดเดียวกันทุกสายงานเพื่อให้เทียบข้ามอาชีพได้

**Requirements 7 รายการ** — วุฒิ ประสบการณ์ ใบขับขี่ ยานพาหนะ ภาษา
สิ่งเหล่านี้เป็น**เงื่อนไขคัดกรอง ไม่ใช่ทักษะ** จึงแยกออกไม่ปนกับสถิติทักษะ

> [!important] สิ่งที่ไม่ใช่ทักษะและต้องไม่อยู่ในทะเบียน
> **ชื่ออาชีพ** (พยาบาล เชฟ) · **ชื่ออุตสาหกรรม** (ก่อสร้าง เกษตร) · **รูปแบบการจ้าง** (งานประจำ ทำงานเป็นกะ)
>
> สิ่งเหล่านี้บอกว่า "งานอยู่ในวงการไหน" ไม่ได้บอกว่า "ผู้สมัครต้องทำอะไรเป็น"
> ทะเบียนรุ่นแรกเคยมีรายการอย่าง `งานสุขภาพและพยาบาล` และ `งานอาหารและเครื่องดื่ม`
> ซึ่งเป็นอาชีพ ไม่ใช่ทักษะ จึงเขียนใหม่เป็น `Clinical & Nursing Practice`
> และ `Food & Beverage Preparation` ที่ระบุ**การปฏิบัติ**แทน

การจัดหมวดที่แก้ตามนิยาม — `Negotiation & Persuasion` และ `Presentation & Public Speaking`
เคยอยู่ฝั่ง Hard แต่ตามเกณฑ์แล้วเป็นทักษะระหว่างบุคคลที่ใช้ข้ามสายงานได้ จึงย้ายมาเป็น Soft

`PLC & Industrial Automation` แยกออกจาก `Electrical Systems` โดยตั้งใจ
เพราะเป็นทักษะคนละระดับ — ช่างไฟเดินสายไม่ได้แปลว่าเขียน ladder logic หรือตั้งค่า inverter ได้
และเป็นทักษะที่หลักสูตรวิศวกรรมสอนได้ตรง จึงควรนับแยกให้เห็นอุปสงค์จริง

> [!warning] บทเรียนจากการปรับ pattern
> pattern ที่กว้างเกินไปจะจับ**หัวข้อ** **สวัสดิการ** หรือ**ข้อความโฆษณาบริษัท** แทนทักษะจริง
> ที่พบและแก้แล้ว:
> - `เงินเดือน` → "การปรับเงินเดือนประจำปี" ในหัวข้อสวัสดิการของทุกประกาศ
> - `ฝึกอบรม` → "การฝึกอบรมและพัฒนาพนักงาน"
> - `ความรับผิดชอบ` → หัวข้อ "หน้าที่และความรับผิดชอบ"
> - `ละเอียด` → "รายละเอียดงาน"
> - `สิ่งแวดล้อม` → "บรรจุภัณฑ์เพื่อสิ่งแวดล้อม" ในข้อความแนะนำบริษัท
> - `ขับขี่` → "ใบขับขี่" ซึ่งเป็นเงื่อนไขคัดกรอง ซ้ำกับ `REQUIREMENT_TAGS` อยู่แล้ว
>
> ก่อนแก้ ทักษะเหล่านี้แสดงผลสูงถึง 39.6% ซึ่งเป็นตัวเลขเท็จทั้งหมด
>
> อีกกรณีหนึ่งคือจับถูกแต่**จัดหมวดผิด** — `ประสานงาน` เคยถูกนับเป็นงานเอกสาร
> ดันหมวดนั้นขึ้นไป 44.7% ทั้งที่การประสานงานข้ามฝ่ายผลิต/QA/จัดซื้อ
> เป็นความสามารถคนละอย่าง จึงย้ายไปเป็น `Cross-functional Coordination` ฝั่ง Soft

## วิธีรัน (ต้องมี Node.js ≥ 18)

```bash
cd kalasin-jobs
npm install
npm run build:data
npm run dev
```

## การอัปเดตข้อมูล

```bash
npm run scrape:all
```

เก็บใหม่ทั้งสามแหล่งลง `data/raw-*.json` แล้วรัน `npm run build:data`
เพื่อรวมข้อมูล สกัดทักษะ และสร้าง `src/jobsData.json` ใหม่
คำสั่ง `npm run build` เรียก `build:data` ให้อัตโนมัติผ่าน `prebuild`

สคริปต์แยกรายแหล่งได้ด้วย `npm run scrape:jobthai` · `scrape:jobtopgun` · `scrape:jobbkk`

## Deploy บน Vercel

repo นี้มีเว็บอยู่ในโฟลเดอร์ย่อย จึงต้องตั้ง **Root Directory** เป็น `kalasin-jobs`
`vercel.json` ตั้ง rewrites ให้ทุก path กลับไปที่ `index.html` แล้ว ซึ่งจำเป็นสำหรับ client-side routing

## ข้อจำกัดที่ต้องรู้ก่อนใช้ตัวเลข

1. **ไม่ใช่สำมะโนตลาดแรงงาน** — งานภาคเกษตร ราชการ และธุรกิจครอบครัวในกาฬสินธุ์
   จำนวนมากไม่เคยผ่านเว็บหางาน ตัวเลขนี้เป็นภาพของ "ตลาดแรงงานที่ประกาศออนไลน์" เท่านั้น
2. **หน้ารายการไม่รองรับการแบ่งหน้าฝั่งเซิร์ฟเวอร์** — JOBBKK รายงาน 36 ตำแหน่งแต่ส่ง HTML มาน้อยกว่านั้น
   และ JOBTOPGUN ละเลยพารามิเตอร์ `page` จึงชดเชยด้วยการไล่หน้าแยกตามสายงาน แต่ยังไม่ครบ
3. **ผลค้นระดับภาคปนมากับระดับจังหวัด** — ตัดออกแล้วตามหลักการนับข้างต้น
4. **สกัดด้วยการจับคู่คำ ไม่ได้ใช้โมเดลภาษา** — ต่างจาก `curriculum-graph` ที่ใช้ Gemini
   วิธีนี้จับทักษะที่เขียนด้วยถ้อยคำนอกทะเบียนไม่ได้ และไม่เข้าใจบริบทเชิงปฏิเสธ
   เช่น "ไม่จำเป็นต้องมีประสบการณ์"

ตัวเลขทั้งหมดสะท้อนเฉพาะสิ่งที่นายจ้าง**เขียนระบุไว้ในประกาศ**
ทักษะที่ไม่ถูกเขียนถึงไม่ได้แปลว่างานนั้นไม่ต้องการ
